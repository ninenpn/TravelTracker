## Data model (spreadsheet-shaped on purpose)
Every tab is a list of rows; a row is a JSON array of strings (`cells`).
- `sheet_rows(tab, row_no, cells)` — **public** trip (Almaty). Tabs: `plan`, `Users`, `Expenses`, `Locations`, `Places`, `Stay`, `Tips`, `ค่าใช้จ่าย`. Row 0 is the header.
- `private_rows(trip, tab, row_no, cells)` — other trips (`macau`, `nagoya`, `kunming`, `xian`): tabs `plan`, `Cost`, extras, plus `media` (picture index) and `media:<id>` (base64 JPEG in ≤150 k-char chunks).
- Private/secret tables: `trip_members`, `member_pins(name, hash)`, `pin_fail`, `app_secrets` (edit-code hash), `sheet_history` (plan snapshots, ≥10 min apart, last 30).
- `Users` tab: `Name, Budget[, Budget <CUR>]` — the list of members (PIN values are **not** here).
- `plan` tab columns: `Day, Start time, Start Location, Arrive time, Arrive Location, How to Travel, Note` (+ `Notice`, `Tickets`, `Location`). A row with text in `Day` starts a new day; rows with a text-only `Start time` are free-text lines; a row `Day2`/`Day4`… in the start-time column after the last day = "ideas" block.

## Read path (`app.js`: `fetchTab` → `fetchSb` / `fetchPriv`)
- Public tab: `GET /rest/v1/sheet_rows?tab=eq.<tab>&order=row_no` with the publishable key; if the table is missing/unreachable → Google Sheet gviz CSV (Almaty only).
- Private trip: RPC `get_private(trip, tab, name, pin_hash)` → rows or `null` (not allowed). Open access: the server accepts any name in `trip_members` (Nine, Mew) and ignores the hash (the client sends the constant `'open'`).
- `load()` fetches plan first, then the other tabs in parallel.

## Write path
- Public trip: RPC `save_tab` (replace a whole tab atomically, with history), `append_row`, `upsert_row` — take **no edit code** since `docs/supabase_nocode.sql` (owner's decision; the `code` parameter is kept but ignored so old clients work; `check_code` always returns true). `save_tab` still refuses an empty plan and snapshots into `sheet_history` (>= 10 min apart, last 30 kept) so a bad overwrite can be restored.
- Profile photos: `member_avatars(name pk, mime, data, updated_at)` (RLS, no grants) via `avatar_list()` / `avatar_put(name,hash,mime,data)` / `avatar_delete(name,hash)` (`docs/supabase_avatars.sql`; name must be in the Users tab, image/jpeg|png|webp, <= 120k base64 chars). Central: anyone may set/remove anyone's photo. Client: `avatar()` renders `<img>` or initials in a fixed-size circle, `avRefresh()` swaps in place (no re-render / no layout shift), cache `localStorage['tt.av']` <= 300 KB, RPC missing -> initials only + Thai hint on upload.
- Private trips: RPC `private_write(trip, tab, op, payload, name, pin_hash)` with `op = save|append|upsert`.
- The plan is saved by rebuilding all rows from the in-memory structure (`planToRows`) — raw rows are kept per step (`_row`) so unknown columns survive. Saving never clears first: the function replaces the tab in one transaction; an empty plan is refused.

## Auth model
- **Open access, no login (owner's explicit decision after being warned).** `docs/supabase_open.sql` redefines `_pin_ok` (true for any non-empty name listed in the public `Users` tab; no hash check, no throttle) and `_member` (name is a row of `trip_members`), and deletes every `trip_members` row except Nine and Mew. Signatures, grants, RLS and tables are unchanged, so anon still cannot read/write tables directly, only call the RPCs. The old PIN objects (`member_pins`, `verify_pin`, `set_first_pin`, `reset_pin`, `pin_status`, `pin_fail`) stay in the database but nothing uses them.
- Client: no login screen and **no user identity** (no `me`, no `tt.me`, no switch-name UI). `travellers()` = Users tab on Almaty, `PRIV_TRAVELLERS` (Nine, Mew) on any private trip; it only feeds pickers (who paid, whose document, whose location). Every RPC goes out with `apiName()` = `travellers()[0]` (the constant API identity) and `myHash()` = `'open'`. Because the identity is fixed, the server rules are central too (`docs/supabase_central.sql`).
- **Consequence (accepted by the owner):** anyone with the link who knows or guesses a member name can read the private trips and every personal document (ID scans) and write to private trips / documents. Public-trip writes (`save_tab/append_row/upsert_row`) need no code either, so anyone with the link can rewrite the Almaty plan (history keeps 30 snapshots). Everything public (Almaty plan, expenses, Tips) is readable by anyone with the link.

## Trip status
`PRIV_TRIPS` (in `app.js`) carries `start/end`; Almaty's range is learned from its plan (`cfg.dates[tripId]`, default 2027-02-13…18). `tripStatus()` → `current | upcoming | past`; `tripList()` filters (default Current+Upcoming) and sorts; the picker is the title tap (top-left) and the Menu card.

## UI structure
Tabs (bottom nav, 5 items): **แผน** (plan: one slim "เปิดแผนที่" row (`#homeDock`/`#dockFull`, fixed 52 px, no inline map) + sticky day bar, the next-stop hero `.cd` (gradient; bell / stay / info icon buttons), day title + ล็อกวัน / แก้ไข buttons, steps (flat cards, meta as muted inline text) each with a "นำทาง" icon button, stay badge on steps that go to the stay, ideas; in edit mode a sticky bottom bar `.editbar` with เพิ่มรายการ + เสร็จ) · **ค่าใช้จ่าย** (one page, see below) · **สถานที่** (one page, see below) · **เอกสาร** (see Documents) · **เมนู** (สมาชิก, ทริป, การแจ้งเตือน, โหมดมืด, pictures / extra tables, refresh, then the Supabase usage card LAST; no profile card, no edit card). There is no Map tab and no inline map: the "เปิดแผนที่" card and the day-bar "แผนที่" button open the **full-screen overlay** (`#mapOv`) directly. **Leaflet is created lazily on the first open** (`openMapOv` -> `mountMap` -> `ensureMap`): before that there is no `#map`, no tile request and no layout. The one instance then stays inside the overlay; later opens do not re-fit. Back / Esc / x close it (`history.pushState` + `popstate`; Esc closes the card / filter sheet first).
Scroll behaviour: **no scroll-linked JS**. `#homeDock` (the open-map card) is in normal flow and scrolls away with the page; only `#homeDays` (`.daybar`: day chips + a "แผนที่" button that opens the overlay) is `position:sticky` at `--topH`, with a faint shadow + blur. No transform/transition/`will-change` on either. `html{scroll-padding-top}` = header + day bar (`--dockH` = day bar height) so scrolled-to steps are never covered. A day change smooth-scrolls to the day heading only if the reader is already past it (auto behaviour under `prefers-reduced-motion`).

## Design system (style.css)
`style.css` is organised as tokens (`:root` + dark overrides) → base → header/nav → primitives (card, chip, btn, icon buttons, tag, seg, switch, tappable rows) → plan → ค่าใช้จ่าย → places → menu/forms/sheets → map pins + overlay → documents. Everything uses the tokens (accent, surfaces, 5 type steps 13/15/17/21/28, 4/8 spacing, radii 12/20, elevations e1/e2). Rules and the affordance conventions are listed in CLAUDE.md ("UI design system") and enforced by `tests/design.js`. The countdown sheet has no name footer (only a close button).

## Stability rules (the UI must not "bounce")
- **Refresh = compare, not re-render.** `load()` builds the new data, serialises the parsed tabs (`snapOf`, time-derived `dt` excluded) and compares it with `ui.sig`. Identical → nothing is touched (no `#tl`/`#homeDock`/`#map` replacement, no `drawMap`, scroll untouched). Different → `applyData` re-renders inside `keepScroll` (anchors on the first visible step). Under an open dialog / focused field / lightbox the new data waits (`ui.stale`) and is applied on close. A tab that fails to load keeps its last good copy; a failed plan fetch never wipes the screen.
- **Trip switch never blanks**: the previous plan stays (dimmed, sub-title "กำลังโหลด…") or the cached copy of the new trip is shown at once; nothing is cleared before new data arrives.
- **Reserve space**: sub-title, day bar and map have fixed/min sizes so late data cannot shift layout (CLS <= 0.05 in tests). Animate only `transform`/`opacity`.
- **Tabs**: each remembers its scroll (`ui.scroll`) and is re-rendered only when `ui.tabVer[tab] !== ui.ver` (`ui.ver` is bumped by `renderAll`, plan edits, spot/place changes).
- **Offline cache (stale-while-revalidate)**: `localStorage['tt.cache.<tripId>']` = `<time>\n<snapshot JSON>` of the last good data (skipped if > 1.5 MB; never picture chunks). Boot and trip switch render it immediately, then refresh; sub-title shows "กำลังอัปเดต…", and "ออฟไลน์ — แสดงข้อมูลล่าสุด HH:MM" when the network/RPC fails (no red error box when something is already shown). Private-trip caches (`tt.cache.priv:*`) are removed when a different traveller name is chosen (`#btnMe` list).

## Plan extras (day lock, stay badge, quick info)
- **Day lock**: public/private tab `Locks` (`Day, Locked 0/1, By, Time`; key = the day label), read by `load()` (`data.locks`, part of the cache snapshot, `noSheet`), written by `setDayLock()` through `sheetApi.call('upsert')` (`upsert_row` / `private_write`; the header row is appended once if the tab is empty). Optimistic UI; a failed write reverts and shows a toast. **Soft lock**: `isLocked(day)` is checked by the app (edit button disabled + badge "ล็อกอยู่ · who", `toggleEdit`, `addToPlanDialog`, `addSpotToPlan`, the spot-dialog day picker, the step dialog's day picker). The server does not enforce it: anyone calling the API directly can still change a locked day.
- **Stay = a place**: `isStayPlace(name)` (the words ที่พัก/hotel/accommodation or the Stay name) puts a small bed badge on plan steps (`placeHtml`); tapping it (or the "ที่พัก" button of the next-stop row) opens `stayDialog()` (bottom sheet): name, platform, address, check-in/out, booking ref (copy), phone (tel:), note, rules, navigate (`navLinks`), copy address, taxi screen. `parseStay` also reads `checkout`, `booking|ref`, `phone`.
- **Quick info**: other optional `Info` rows (Key,Value) open from ONE icon button (`#infoBtn`, aria-label "ข้อมูลด่วน") in the next-stop row -> `infoDialog()`; no card, no vertical space.

## ค่าใช้จ่าย (tab money) and สถานที่ (tab spots)
- **ค่าใช้จ่าย** `renderMoney`: for each currency that has entries one card (`.card.cur[data-cur]`): rows per traveller = amount paid (+ "ส่วนที่ต้องรับ" = their share) and the net pair debts "A ต้องจ่ายให้ B" (`calcCur().pairs`); below, the expense list (no "mine" filter: there is no identity). The add form needs a payer ("ใครจ่าย", required, no default) and a target: ส่วนกลาง / ส่วนตัวของคนเดียว (one person) / แบ่งกับบางคน (several); on save one person other than the payer is written as `split` with that person, the payer himself as `personal`. Travellers = `travellers()` (Nine and Mew for private trips). `allExpenses()` = Expenses tab + `costExpenses()`: the Cost tab of private trips (or any Cost tab with person columns) — columns "นาย" (Nine) / "มิว" (Mew) are personal amounts, a row without a person amount takes the amount column (ราคา/ส่วนกลาง) as a shared cost with no payer (split, never a debt); rows named รวม/total are skipped. No budget donut, no category table, no final table. Rows of the `Expenses` tab without PaidBy are `pending` (`pendingExpenses()`, excluded from `allExpenses()`/`calcAll`): `pendingHtml()` renders card `#pendCard` per currency, also when that currency has no per-person data. The `Stay` tab key `Chat` (http/https only, escaped) adds the Join + copy-link row to `stayDialog`.
- **สถานที่** `renderSpots`: add box (`#linkIn`) accepts a Google Maps link, "lat, lng" or a place name (`geocodePlace` -> Nominatim). `spotDialog` shows the insight BEFORE saving; `analyzeSpot(place)` = nearest plan stops of the upcoming days (distance + walk/drive estimate `legEst`: walk up to 1.5 km else ~27 km/h by car) + the first gap (earliest day, smallest detour) where `arrive(A) + travel(A->place) + visit + travel(place->B) + 5 min <= arrive(B)` and the time of day/meal fits (`visitOk`). `saveSpot` re-renders at once: Suggestion cards ("แทรกหลัง X ช่วง hh.mm–hh.mm, เดิน N นาที" + "แทรกเข้าแผน" = `addSpotToPlan`) + the list of saved places with their insight. Nothing is built in: an empty `Places` tab shows the empty state. Tips ("น่าไป") are a collapsible section below.

## Documents (tab เอกสาร)
- **Server** (`docs/supabase_docs.sql`, run by the user after the other docs/*.sql): tables `member_docs(id, scope person|shared, owner, trip, title, kind, mime, size_bytes, note, created_by, created_at, chunks)` + `member_doc_chunks(doc_id, i, data)` (base64 in <=300k-char chunks); RLS on, **no** grants to anon/authenticated. RPCs (SECURITY DEFINER, name via `_doc_auth` -> `_pin_ok`; after `supabase_open.sql` the hash is ignored): `doc_list` (metadata of ALL documents), `doc_get` (chunks, `null` if unknown), `doc_put(..., p_owner default null)` (for scope person the document belongs to `p_owner`, default the caller; `created_by` = caller; returns the id as text or `-1` auth, `-2` MIME, `-3` > 6 MB base64, `-4` limit 40 personal / 60 shared, `-5` bad title/scope/chunks, `-6` unknown owner; limit 40 is per owner), `doc_rename`, `doc_delete` (1 ok, 0 not found, -1 auth, -5 bad title). Policy (deliberate, owner's decision): documents are visible to every accepted member and any member can add a document for another member; after `docs/supabase_central.sql` ANY accepted member may rename/delete ANY document (the base `supabase_docs.sql` still has the old owner-or-uploader rule until the central file is applied). Allowed MIME: jpeg/png/webp/pdf. Honest limit: ID scans are sensitive; after `supabase_open.sql` they are protected only by knowing a member name (every listed name sees every document) and Supabase encryption at rest: effectively readable by anyone with the link (owner's explicit choice). No client-side encryption.
- **Chips** (sticky under the header): ทุกคน (everybody's documents grouped per person in traveller order + a ส่วนกลาง group, headers toggle `dc.open`) | one chip per traveller | ส่วนกลาง. There is no name gate and no "friends" segment. The add sheet asks "เอกสารของใคร" (chips of every traveller + ส่วนกลาง; default = the chosen name / the open chip; Save is disabled until one is picked) and always sends `p_owner` for personal files. "ดาวน์โหลดทั้งหมด" asks a scope (default ของฉัน+ส่วนกลาง; ทั้งหมดในกลุ่ม optional). Rename/delete menu items only when `docCan(d)` (owner or uploader).
- **Client** (`app.js`, section "documents"): `dc` state (list/status/segment), `dv` viewer state. `docsRefresh()` uses `dName()` = `apiName()` (the server only checks that it is a member): `null` (server does not know the name) => Thai toast + retry panel (`docsRejected`), network error => use cached list ("ออฟไลน์" chip) or inline retry, missing function => `DOC_NOSQL` message.
- **Files**: `docBlob()` = IndexedDB (`tt-docs`, store `kv`: `l:<me>` list, `f:<me>:<id>` blob) -> network (`doc_get`, then cached). Thumbnails are fetched lazily (IntersectionObserver) into fixed 84 px boxes, so they also get cached. `docsWipe()` (called from `clearPrivCaches` on a traveller change, and from `syncMe()` when the effective name changes) bumps `dc.epoch` (in-flight work is discarded), revokes blob URLs and deletes the database.
- **Upload**: images are downscaled (longest side <= 1800 px, JPEG q 0.82), PDFs <= 4 MB, sent by XHR (for progress) as chunks in one `doc_put`.
- **Viewer** `#docOv`: white full screen, pointer-events pinch/pan/double-tap, rotate, swipe/arrows between docs of the segment, Wake Lock when available (else hint), `history.pushState` so Back closes, `html.noscroll`. PDFs are shown inline: pdf.js 3.11.174 (`cdnjs.cloudflare.com/ajax/libs/pdf.js/…`, SRI hash, loaded on the first PDF only) renders each page to a JPEG canvas (max 40 pages) into `#dvPin`; pinch / double-tap zoom widens the page list (panning = native scroll). Rendered pages are cached in IndexedDB (`p:<name>:<id>`) so the next open needs neither network nor pdf.js; `#dvOff` shows "บันทึกออฟไลน์แล้ว" (also for images, which are cached by `docBlob`). If pdf.js cannot load / read the file, the old "เปิด PDF" button (blob in a new tab) is the fallback. The same overlay shows the **taxi screen** (stay name + address in huge type).
- **Quick info** moved to the plan tab (see Plan extras): `data.stay` (Stay tab) + optional tab `Info` (Key,Value rows, `parseInfo`, fetched with `noSheet`, part of the cache snapshot). Nothing of it remains in the documents tab.
- Share: `navigator.share({files})` if `canShare({files})`, else `<a download>`, else `window.open(blobUrl)`.

## Maps, filters, navigation, location sharing
Leaflet + OSM tiles; geocoding via Nominatim (cache `tt.gc2`), routing via routing.openstreetmap.de (cache `tt.trv`); estimates are marked `~`. Geocoding/routing only run once the overlay is open. Location tracking is only requested between the first flight's arrival and the last flight's departure (`gate()`).

**Overlay layout**: top bar = layer chips (เส้นทาง · ร้านอาหาร · ที่เที่ยว · ที่พัก · สถานี/ขนส่ง · อื่นๆ · เพื่อน) + "ตัวกรอง" button (badge = number of active filters) + x; map; status bar = geolocation status + sharing switch. Pins: plan stops are classified by `wpKind` (stay = "ที่พัก"/hotel words, transit = station/train/metro/bus/airport words, else route); the route line belongs to the เส้นทาง layer, each pin kind to its own layer.
**Filters** (`ui.f`, saved in `localStorage['tt.f']`): layers on/off, `day` (`'sel'` = day chosen in the plan tab (default) / `'all'` / `'today'` / day index), `hide` (friends not shown), `todo` ("เฉพาะที่ยังไม่ไป": finished stops of today are dropped via `stillAhead`; default off = all stops of the chosen day). "รีเซ็ต" restores `F_DEF`. The bottom sheet is `#ovSheet` (`renderSheet`).
**Navigation**: ONE helper `navLinks(place, mode)` builds every action: `https://www.google.com/maps/dir/?api=1&destination=LAT,LNG[&travelmode=walking|transit|driving]` (coordinates when known, otherwise the place name), the coordinates text and a share link. `navModeOf(how, name)` picks the mode from "How to Travel" (taxi/Yandex/Grab = driving; train/metro/bus/station = transit; walk = walking). Used by the plan-step icon button (`stepNav`), spot cards (`navA`), the stay panel and the overlay bottom card (`showCard`: name/details/time, segmented เดิน/ขนส่งสาธารณะ/รถ (last choice in `tt.navMode`), primary "นำทางด้วย Google Maps", "คัดลอกพิกัด", "คัดลอกลิงก์"). For transit/taxi items the card adds the hint "ในคาซัคสถานแนะนำใช้ 2GIS / Yandex Go / inDrive คู่กับ Google Maps" (hint only). **There is no 2GIS link**: no documented 2GIS URL form could be verified on docs.2gis.com, so none is built.
**Friends / sharing**: the public tab `Locations` (private trips: `private_rows` tab `Locations`) has columns `Name, Lat, Lng, Label, Updated (ISO)`; `parseLocations` reads it with every `load()`. Friend markers = avatar circle (initials fallback) + "x นาทีที่แล้ว", muted after 30 minutes. **Sharing is opt-in, per trip (`tt.share.<trip id>`), off by default**; turning it on shows a consent dialog that also asks "แชร์ตำแหน่งของใคร" (one traveller, required; kept per device in `tt.shareAs` only as the label of the row, not a login; stop/delete uses the same name); then `pushLoc()` writes that name's row through the normal write path (`sheetApi.call('upsert')` -> `upsert_row` / `private_write`, no edit code) on the first fix and about every 45 s while the app is open (and a header row is appended once if the tab has none). Switch off = stop writing (last position stays). "หยุดแชร์ + ลบตำแหน่ง" blanks the row of the share name (Name only, no SQL change needed: there is no delete RPC; blank rows are ignored by the reader). **Locations are visible to everyone who has the link** (public tab / no PIN by the owner's decision).
